# v48 Schema 命名与结构政策

本轮以相同完整输入的独立生成作为一致性范围。产品提示版本为
`ttp-generator-v48-schema-naming-and-structure-policy-zh-cn`，单个 Schema Agent
仍直接调用 `submit_result_schema(result_schema)`，首份合法提案深拷贝冻结。

## 生成政策

同一次生成按独立业务值、实体归属、object/array、名称、完整性复核的顺序决策，
不增加中间产物、工具、确认或额外模型调用。根描述整份输出；平面属性直接属于根；
固定角色章节使用 object；由实例标识区分的同类块及表格使用 array，即使只有一个实例。
子项和汇总归属于其真实父对象，不按字段类型或装饰标题增加容器。

可靠英文标签保留词序、缩写、限定和单复数，仅规范为合法 snake_case。多行表头只组合
同列限定。容器按明确集合/章节标题、实体标签、语义兜底的顺序命名。冲突先使用真实限定，
无可靠标签、拆分子项或合法性例外才使用语义名称。规则不修改业务值，也不阻止独立值拆分。

这些是模型指导，不是确定性语义验证。类型、required、description、约束、采样及默认预算
保持既有政策；公共 API、外部注入、TTP 提示和冻结机制兼容。v44 协议止损和 DeepSeek
输出参数修复继续生效。历史编译器和实验工厂不进入产品运行。

## 离线验收

从实际提示提取独立合成 Schema，通过共用校验器和独立预期 records 检验实体数量、
固定章节、子项、汇总、空槽和缺键。合法反例固定语义门禁的边界。实际 HTTP 模拟验证阶段隔离。
完整离线 pytest、JavaScript、Ruff、格式、diff 检查以及默认/full-scope preflight/baseline
必须通过；AST 比较确认 TTP、任务构造和重试提示正文未变，标准资产不修改。

## 真实评测

只运行一批 56 次 Schema-only：ID `1,3,5,6,7,9,10,11,13,14,16,17,18,19`，
各默认 `001.txt`，重复 4 次、全局并发 4。唯一入口 `scripts/run_test_sets.py run --mode schema-only`
调用公共 `propose_schema()`，每次独立生成器，重复使用同一内存输入快照，不传入评测答案。

deepseek-v4-flash、temperature 0、非流式、输出预算 8192、context 128000、HTTP 120 秒、
模型重试 2、总预算 1800 秒和 26 轮；TTP 提交 18、独立测试 3 在本模式不使用。
其余 model/policy 逐项匹配既有记录，保留 Thinking 计数和 DeepSeek 参数映射。
输出预算含供应商推理 Token，不能解释为 8192 个可见 Schema Token。

启动前核验 Laminar 写入、flush、回读和正文访问，记录 revision、dirty、输入路径及采样事实。
不补跑失败 trial，不重跑历史组。逐条审阅 56 次及最多 84 对有效提案。
Trace 正文仅经获授权的只读通道在分析内存处理，不落盘、不保存内容哈希、不回灌模型。

审阅 v2 分开记录规则遵循、七维业务合理性和命名/层级一致性；旧 metrics v2、runner v5
及联合指标含义不变。合理但违反标签政策可以业务可接受、规则不通过；相同错误不能算业务通过。
本轮提案通过要求生成复验成功、业务可接受、适用政策通过且证据完整。
失败、未完成审阅及未知不算通过。可解析性标记 `not_tested`。
