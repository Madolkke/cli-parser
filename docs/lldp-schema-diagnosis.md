# LLDP Schema 失败诊断（Thinking 计数修正版）

本轮检查了修复版 LLDP 的 **4 条 Trace、11 次完整提交、12 次独立测试**，并对照
历史 v35 中 3 条曾产生候选的 LLDP Trace。结论是：本轮主要失败来自模板对 TTP
匹配起点、group 范围和自由文本竞争的误用。现有必填字段反馈能定位结果缺失，
但模型把局部实验推广为未验证的结构改写，导致修正反复或引入新错误。

**优先建议下一轮只改进“无自身有效起点、仅包含重复子组的容器”指导**：明确裸标题
不参与匹配，提供经过合成验证的匹配式标题对照，并要求复核子组后的父字段。
该机制与本轮 6 次提交、3 个 trial 的相同尾字段缺失直接对应；只移动 XML 声明
顺序不能修复。这里的覆盖数不是预测可挽救的提交数，多个错误经常共存。

本提交只增加诊断报告和通用合成测试。产品提示、反馈协议、解析规则、预算、依赖、
评测资产均未修改，没有运行新的真实模型评测，也没有自动实施上述建议。

## 逐次独立测试：成功标志究竟验证了什么

下列 11 个成功实验的工具反馈都在下一 LLM 请求中逐一审阅。均为 `scope=parse_only`，
没有 Schema 回验和候选验收状态；不存在把实验结果自动保存为候选的情况。
输入范围按 UI 结构分类，不导出实验正文。T3-X2/X3 使用长输入，结构含两个实体及
尾部章节；未计算内容哈希，不能据此宣称与权威完整输入逐字相同。

| 测试 | 输入范围 | 实际结果与后续意义 |
| --- | --- | --- |
| T1-X1 | 一个缩减实体，描述与后续标量 | 描述捕获后续标量，相关字段缺失；证明宽捕获有问题，不是修正成功 |
| T1-X2 | 一个缩减实体，增加管理和重复子组 | 部分子组出现，描述仍被后续标签替换，尾字段仍缺；未验证第二实体、MED 或完整根 |
| T1-X3 | 两个极简实体、两种管理章节形式 | 只产生一种管理分支；不支持随后新增大量未命名标量 group |
| T2-X1 | 两实体的管理分支和相邻标量 | 两种形式都生成管理 object，其中一种为空；只支持容器存在，不保证状态值保留或全 Schema 通过 |
| T2-X2 | 一个缩减实体，描述、管理、重复子组与尾字段 | 描述及子组后的尾字段缺失，解析仍成功 |
| T2-X3 | 单独描述与后续两个标签 | 返回包含空 object 的结果；没有验证成功的描述提取 |
| T3-X1 | 一个较长实体、缩减模板 | 保留部分标量与重复子组，描述和尾字段仍缺，另有 TTP 外壳 |
| T3-X2 | 两实体与尾部章节、缩减模板 | 去掉 `^` 后描述出现但吸收其他章节；未命名子组把实体拆成 4 个片段，汇总另成对象 |
| T3-X3 | 两实体与尾部章节、扩展模板 | 静态 `ttp.incompatible_argument_pipe` 拒绝，无 worker 解析；下一请求仅有 sidecar，无法审阅实际消息正文 |
| T4-X1 | 两个简化实体，一个无描述段 | 宽捕获收进无关行与尾字段；无描述段的实体也出现描述，不能视为忠实解析 |
| T4-X2 | 两实体、管理变体与连续子章节 | 管理丢一分支，宽列表吞入其他章节字段，尾字段缺失；没有完成目标边界验证 |
| T4-X3 | 两个缩减实体、描述与根汇总 | 描述仍缺；随后完整提交同时调整描述、管理和能力列表，未逐项做成功对照 |

这里观察到的是模型能识别部分失败并尝试修正，但实验设计和结论外推不足。
不能从 parse-only 成功推断模型误读了成功标志，也不能把所有失败概括为“忽略反馈”。
T1-S3 后模型明确撤回碎片化结构；T2-S2 后恢复子记录；T4-S2 恢复部分字段，均表明
反馈对后续改动有实际作用。多因素改写使成功与回退难以隔离，剩余预算又限制验证。

## 通用合成复现与反例

测试使用锁定的 TTP 0.10.1，全部通过现有白名单检查和隔离 spawn worker；涉及
完整验收的用例另经根 record 映射和 Schema 校验，M2 正则实验只执行 parse-only。
不在主进程实例化解析器。每个失败/对照只改变一个因素；
矩阵测试用于区分相关但不同的因素。失败模板预期被 Schema 拒绝也是测试通过条件。

| 机制 | 单因素失败 / 对照 | 断言与限制 | 对应当前提交 |
| --- | --- | --- | --- |
| M1 自由文本与同组字段竞争 | 同一捕获行无缩进 / 与合成正文一致缩进 | 前者吞后续状态、Schema required 拒绝；后者重复实体字段完整且保留换行。相同缩进后续内容仍会追加，证明缩进不是结束边界 | T1-S1；T1-S3 共存但不是碎片化首因 |
| M2 变量正则语义 | 变量 `re` 的捕获起点有未启用 multiline 的行首断言（如 `^.+`）/ 去掉该断言；多个 `re` / 一个连续断言或独立排除过滤器 | 前者无匹配；多 `re` 是 OR 而非相交；不把其他位置的 `^` 或 `exclude_re` 内合法锚点泛化为错误 | 带该起点断言的 T1-S2/S4、T2-S1、T3-S1、T4-S1，共 5 提交 / 4 trial；多 `re` 误用仅 T1-S2，实际被锚点失配遮蔽 |
| M3 只有重复子组的容器缺有效起点 | 裸标题 / 同标题匹配式 ignore；交叉尾字段声明前后 | 裸标题时子列表能产生但后续父字段及总数丢失；有效起点恢复。移动声明位置独立地无效；中间缺可选段、随后再出现均覆盖 | T1-S1/S2/S4、T2-S1/S3、T3-S1，共 6 提交 / 3 trial；T1-S3 另受碎片化影响，不加入该独立归因数 |
| M4 不同章节形式共用单一起点 | 同样匹配行放一组 / 分为两个同名组 | 单组只保留首个起点的分支，拆组恢复两种；缺可选章节的实体不生成对象；不声称任意后续模式都能开始 group | T1-S1/S2、T4-S1，共 3 提交 / 2 trial；T1-S3/S4 公共前缀另列 U1 |
| M5 根起点和完整行匹配 | 尾汇总作为首个根模式 / 增加早期完整标题；不完整 / 完整标题 | 前者只剩尾字段；完整锚点恢复。反例：无锚点但先声明子组可保留子对象而只丢可选尾字段，Schema 仍通过 | T2-S2/S4，共 2 提交 / 1 trial |
| M6 未命名子组拆散实体 | 每个标量独立包装 / 同一父组内标量 | 两份输入的 5 个实体分成 10 个片段；撤回包装恢复实体和尾字段；可选子段不串组 | T1-S3，1 提交 / 1 trial；另见 T3-X2 |
| M7 匹配模式宽度 | 同一 WORD 模板的单词 / 多词输入；同一多词输入的 WORD / ORPHRASE 模板 | 只丢目标字段，子列表与总数保持；仅放宽该字段模式可恢复；区分普通模式失配与 group 范围 | T2-S1 的名称，1 提交 / 1 trial；不是 JSON 类型转换错误 |
| M8 跨章节的当前组竞争 | 父级是否排除子组未捕获的中间说明行 × 该行有无 | 仅“中间行存在且父可捕获”失败：父 notes 被替换，子字段缺失；排除该行恢复。没有中间行时宽规则也能正常，防止过度归因 | T4-S2 有直接字段流向证据；T4-S1 是更宽列表的相关竞争，完整链列 U2 |

TTP 源码为这些实验提供解释：变量的多个 `re` 累加后合并为交替；行正则先消费

这些属于当前锁定版本行为，不推论未来版本。没有引入模板自动重写或扩大白名单。

## 未解决项与建议排序

明确未解决的证据缺口：

- **U1：T1-S3/S4 管理公共前缀的具体失配。** UI 已看到字段缺失和公共前缀结构，
  M4 只稳定复现原先的替代分支起点问题；不能把它套用于全部 5 次管理字段缺失。
- **U2：T4 的完整 MED 字段丢失链。** S1 可见多个章节标量进入能力列表，S2 可见
  多个 MED 标量进入描述并替换原描述。M8 稳定复现竞争与重置，但未逐字段复现
  S1 全空 MED、S2 的 `location` 丢失及所有重复列表生命周期。
- T1-S4、T3-X3 的下一请求正文不可核验；T2-S4、T4-S2 无下一请求。均不标为
  “模型忽略反馈”。所有 23 个工具已入表，未知项没有以零或确定归因填补。
- 本轮没有数值/布尔类型拒绝，不支持调整类型转换或 Schema。描述标签混入、
  可选字段缺失和空对象内容仍可能通过 Schema，不能把诊断条数降低等同准确率提升。

| 1 | 明确无自身有效起点、仅含重复子组的容器如何开始匹配，提供裸标题/匹配标题合成对照；复核其后的父字段 | M3，6 次提交 / 3 trial；2×2 单因素矩阵及历史候选均支持 | 低到中：提示可能影响其他结构，不能宣称所有裸行非法；先提示专项，不自动拒绝或重写合法模板 |

继续保留默认；Power 末次提交 finish、120 秒启动门槛、完整上下文保护继续独立处理。

当前 v35 提示已经包含章节标题、重复子章节和尾部根字段原则；推荐不是简单重复
这些原则。具体差距是示例未直接展示“容器没有自身字段、只包一层重复子组”时，
裸标题仍让子列表产生、却丢失父尾字段的失败/对照。下一轮宜替换或收紧相邻的
章节示例，保持提示体积可控；是否增加静态提示需要另行设计误报边界，不能因
本轮局部现象把全部裸文本标题设为拒绝条件。
