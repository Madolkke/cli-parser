# SchemaPlan 预试结果与采用决定

本轮候选未达到预试资格，停止于 36 次 Schema-only 请求，不启动后续 112 次端到端对照。
共同底座 A 生成与复验通过 12/12；结构化计划 B 与增加确认的 C 均仅通过 1/12，
各自唯一的冻结提案仍存在独立业务值合并问题。产品默认保留 A（v44）及已验证的可靠性修复。
不能据本轮声称 SchemaPlan 改善了业务合理性、独立生成一致性或解析效果。

## 失败主要发生在产出计划之前

22 次失败中，21 次从未产生工具调用：每次连续 4 个实际模型响应都以 `length` 结束，
各消耗 8192 output token，正文和工具调用均为空，仅产生 reasoning。防循环在第四次
无工具回复后按兼容终止原因 `model_no_tool_retry_limit` 停止。

剩余 R032 有 14 次模型调用，其中 11 次以 `length` 结束。原始响应中的 8 个工具调用，
5 个参数 JSON 被截断或语法无效，另 3 个 JSON 合法但错误包入 `arguments`；4 个经框架
修复后进入编译，分别产生 3 次 `schema_plan.invalid_shape` 与 1 次名称冲突拒绝。
最后四轮为无工具、无工具、截断工具入参被框架拒绝、无工具，属于混合协议失败序列，
末轮以兼容分类 `model_no_tool_retry_limit` 终止，不能称为四次连续无工具。
框架入参拒绝、产品编译校验拒绝与输出截断分别统计，不混为 Schema 业务语义失败。

这说明当前来源坐标和实例证据表达的任务负担，在固定 8192 总输出预算下大多没能走到
有效建模提交。它不是证明编译器不能重复编译，也不能仅凭该现象断言唯一原因是计划
序列化大小；本轮没有拆分坐标计算、实例枚举、提示长度和模型推理成本做消融。

额外只读抽查 R010、R011、R014 的首轮推理，观察到逐字符计算并反复修正来源坐标，
同时反复选择拆分粒度、object/collection 及业务角色。这支持“来源证据任务与建模决策
共同占用推理”的解释，但三条抽查不能确定全部失败的唯一原因或各项 Token 占比。
成功计划中的标签末字符遗漏也说明：引用落在合法范围，不等于它覆盖了完整业务标签。

## 按预定门槛停止

B/C 均未达到合法 12/12、可接受至少 11/12、合理一致至少 2/6 pair 的预试条件。
因此不进行 B/C 优先级或 1.5 倍成本择优，也不进入正式端到端采用比较。恢复/保留共同
底座 A，保留已单独验证的可靠性修复、独立诊断测试、评测能力与全部脱敏证据。

本轮能确认的工程收益是协议错误能有界停止、阶段与冻结状态保持隔离，以及评测能分开
报告计划确定性、独立建模一致性和业务错误。候选本身没有达到有效优化标准。
后续若继续，应先让结构化建模在既定输出预算下可靠地产生完整计划，再重新制定实验；
这不是本轮授权的追加优化，不改变门槛、不补跑，也不自动开启下一轮。
