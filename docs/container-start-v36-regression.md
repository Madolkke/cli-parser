## LLDP 容器起点复核

已在 UI 审阅全部 **14/14** 次完整提交。区分模板写法、输出症状和机制对应：

- **8/14 次提交、2/4 个 trial** 的目标容器使用裸标题且没有自身匹配模式：
  L2-S1/S2 与 L4-S1 至 S6。L2-S3 另在容器内部加入父尾行的 ignore，其形成机制不同。
- **8/14 次提交、2/4 个 trial** 收到 `/neighbors/*/media_attachment_unit_type`
  必填缺失诊断：L2-S1/S2/S3、L4-S1/S2/S4/S5/S6。此计数按受影响提交去重，不按 issue
  或数组元素累加。
- **6/14 次提交、2/4 个 trial** 同时具备既有合成 M3 支持的结构与尾字段症状：
  L2-S1/S2、L4-S1/S2/S4/S6。历史对应为 **6/11 次、3/4 个 trial**。
  两组的受影响提交绝对数量仍为 6，不能只凭比例下降认定机制已解决。
- 另 **3 次提交** 不强行归因：L2-S3 有尾行 ignore 竞争，L4-S3 新增未命名尾字段子组
  后返回 `ttp.invalid_record`，L4-S5 将重复子组改为 table。前两类及 table 变体的完整
  因果链未在本轮合成测试中隔离验证，标为未知。
