四份均采用一个根 object 下的重复实体 array，包含 15 个 string 业务字段；
没有确认根粒度、类型、拆分、字段覆盖或值清洗错误。命名完全相同的只有 trial 2 与 3，
这两份仍因末列 required 不同而不构成完整契约一致。

Trial 4 的 `/peer/*/group_organization` 是本批唯一明确的业务错误机制：
把未属于组织列的上层限定拼入该字段，改变了字段含义。末列仍有对应字段，
不能把这一次错接再计算成末列覆盖遗漏。两项端口名称省去可靠限定属于政策偏离，
未另计为独立业务错误。

前三份业务可接受不等于政策证据完整。原始多行表头存在错位，末列上层限定的归属
不足以独立确认，所以三份的 `qualifier_ownership` 保留为 `insufficient_evidence`。
不因合理的命名偏好不同直接判业务错误，也不把推测的完整限定标成已经证实。

表头及值槽存在而值为空时，required string 可以忠实表达空字符串；末列 optional
也未要求丢弃已存在的空槽。本批没有仅因 required 差异判业务失败。所有 description
均已只读审阅；六对未发现说明改变值保真、空槽、单位或捕获边界的要求，
`annotation_semantics` 均为 `equivalent`。这不消除字段命名或政策证据问题。
