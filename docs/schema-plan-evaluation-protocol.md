# SchemaPlan 评测事实与实验协议

本轮验证合理性、独立生成的契约一致性和实际解析效果，三者分别统计。
[业务事实清单](schema-plan-evaluation-facts.json) 在新候选运行前，仅从登记的默认
原始输入建立；不读取标准 Schema、模板或 expected，不从新候选输出反推答案。
它是人工审阅的来源索引，不进入任何产品模型请求，也不是第二套自动解析器。

## 受限事实清单 v1

顶层只允许 `facts_version`、`coordinate_system` 和 `cases`。
版本固定为 1，坐标枚举固定为
`one_based_line_zero_based_unicode_half_open_column`：行号从 1 起，
Unicode 字符列从 0 起；范围包含起点、不包含终点，换行不计入列位置。

每个 case 只包含：

- `dataset_id`、`case_id`、`input_path`：注册表 ID、用例 ID、默认输入路径。
- `entities`：`entity_id`、`parent_id`、`kind` 和 `source`。
- `facts`：`fact_id`、`category`、`presence`、`representation`、
  `mandatory` 和 `sources`。

实体使用本例局部 `e000` 起的无业务含义编号；事实使用 `f001` 起的编号。
实体种类只有 `root`、`section`、`repeated_entity`、`nested_entity`。
父子关系及 source 标明实际原文归属；实体列表顺序表示来源顺序。
section 不强制要求特定 Schema object、array 或命名形式。

source 只包含 `line_start`、`column_start`、`line_end`、`column_end`。
事实来源另含 `entity_id` 与 `role`，role 只能为
`label`、`qualifier`、`value`、`empty_slot`。
同一表列可用一个 fact 和多个实体来源表示；各实体的非空值和空槽分别保留，
不能因列名相同就把不同实体的实际值合并为一次观察。

category 只能为 `identifier`、`text`、`status`、`version`、`build`、
`timestamp`、`duration`、`measurement`、`count`、`category_count`、
`entity_discriminator`、`ordered_values`。
presence 只能为 `present`、`empty_slot`、`present_with_empty_slots`。
本批没有人为添加未出现字段；缺失行处理仍由离线合成测试验证。

representation 的含义为：

| 枚举 | 审阅含义 |
| --- | --- |
| preserve_string | 保留完整逻辑值、值内符号和占位字符串 |
| preserve_string_with_empty_slots | 非空值保真，已存在空槽表达为空字符串 |
| preserve_sequence | 所有值、词项内部边界与顺序均保留，允许合理容器或明确无歧义拼接 |
| integer_or_string | 原文无前导零的纯整数可数值表达或忠实字符串表达 |
| numeric_or_string | 测量数值可按合理数值类型或原始字符串表达 |
| independent_value | 独立业务值必须可区分，不能全部压为无法独立表达的复合原串 |
| preserve_whole_or_semantic_parts | 整体或有可靠业务边界的部分均可接受，必须完整保留信息 |
| preserve_unit_or_explicit_unit | 带单位字符串或在契约中明确单位的数值均可接受 |
| semantic_identity | 可用字段值或明确结构表达身份／业务限定，不要求标签额外复制为值 |

mandatory 是“这项可见业务事实必须被完整表达”的审阅标志，**不是 JSON Schema
required**。它不把所有可见属性自动设为 required，不强制候选采用人工字段名，
也不把合理的替代结构直接判错。实体列表属于审阅证据，不能用来要求一个固定数组名。

label/qualifier 来源只为人工核对业务含义及边界，不要求全部原文字段标签进入解析结果。
独立构建标识中的结构标签、时间/能力值外的布局符号是否去除，按明确结构证据判断；
值内符号、前导零、已有状态和占位字符串不可任意改写。
空槽来源允许真实空白范围或零长度边界，必须同时有真实父实体及标签证据。

本版禁止自由正文、原始标签或值、Schema/模板/records、description、内容哈希。
未知键、未知枚举、重复 ID、缺失父实体、循环父关系、越界坐标、非空 empty_slot
和空 value 均应拒绝。只有审阅内存可以从来源范围读取原文，不可导出值集合。

## 实验预算与评分

真实请求上限 148 次，失败不补跑，不根据预试逐例改提示再进入正式阶段。

- 预试：A/B/C，ID `3,7,9,11,17,18`，各 2 次 Schema-only，共 36 次。
- 正式：A 与选中候选，ID `1,3,5,6,7,9,10,11,13,14,16,17,18,19`，
  各 4 次 end-to-end，共 112 次。
- 全局并发 4，按用例同期轮换入队；同一资产快照并在内存核对输入相同。
- 全部使用 deepseek-v4-flash、temperature 0、非流式、8192 输出配置、128000
  context、HTTP timeout 120 秒、模型重试 2；每请求 1800 秒、26 轮、TTP 提交
  18 次、独立测试 3 次。输出参数映射不能证实时暂停正式模型运行。
- A 是修复运行协议后的 v44 共同底座；B 为计划编译后冻结，C 在相同计划编译后确认。
  不能把 A 报告成原始 v40，也不能把 C 的确认当成确定性语义验收。

B/C 预试资格为合法 12/12、可接受至少 11/12 且不低于 A、合理一致至少 2/6
pair 且不低于 A、无新增明确业务错误及证据完整。都不合格即结束；都合格默认 B。
仅当 C 多至少一份合理提案，或合理提案不下降且多至少两对合理一致 pair，并且
Token、耗时中位数均不超过 B 的 1.5 倍时，选择 C。实现缺陷影响行为时停止该批，
不自动补充请求。

逐条 Schema 沿用七维审阅；有效 pair 审阅契约及说明语义，合理差异与业务错误分开。
端到端额外审阅实体数量/归属、主要业务覆盖、字段保真、空槽/缺键、顺序。
完整生成必须成功、finish、独立终验通过，且 Schema 和解析内容审阅均通过，
才能计入端到端联合通过。证据缺失或独立复核分歧未解决记未知，不计通过。

审阅隐藏 A/B/C 标签；初审者可看到计划结构带来的客观形态差别，因此不宣称完全盲法。
新增错误、全部失败和采用边界项独立复核；复核不改变原始事实清单以迁就候选。
Schema-only 阶段可解析性固定为未测。

正式采用使用 U（合理提案）、J（合理契约及说明语义一致 pair）、K（四次全部
合理一致的用例）、E（端到端联合通过）：

| 门槛 | 条件 |
| --- | --- |
| 工程及合法性 | 离线通过、证据完整，生成和 Schema 复验 56/56 |
| U | 候选至少 max(53, A) |
| J | 候选至少 max(20, min(84, A + 8)) |
| K | 候选至少 min(14, A + 2) |
| E | 不低于 A，A 为 4/4 的用例仍为 4/4 |
| 错误保护 | 无新增经复核确认的用例＋机制；既有机制不扩大 |
| 实质收益 | U/J/K 至少一项严格提高 |

未达到门槛恢复 A，保留已独立验证的可靠性修复与全部报告。三种最终结论为：
合理性/一致性提高且解析不下降的局部有效；上述条件加解析提高的综合有效；
未采用或证据不足。工程门槛不是统计显著性证明。

代码/运行版本、dirty 状态、输入路径、运行与 trial/Trace 标识、受控分类和计数可保存。
Trace 正文仅经授权的只读通道在内存审阅，事实清单和人工结论都不得进入产品上下文。
