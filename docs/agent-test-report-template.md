# CLI 输出解析 Agent 测试报告模板

<!-- markdownlint-disable MD013 -->

本文为手动填写模板。按测试批次复制表格或增加行，再将 `【待填写：具体内容】` 替换为本次测试的数据、证据与结论。占位符不代表零值；未测试、不适用、证据不足和未观测到的数据须明确注明，并说明原因，不得填写为通过。无关附录可以删除，正文中不适用的测试层次应保留范围说明。

填写顺序建议为环境与范围、方法、结果、问题、验收结论，最后完成摘要。每个批次对应确定的代码、模型、提示、输入范围和预算；配置不同的结果分开展示。所有比例同时给出分子和分母，分母为零时标记不可用，不填写为零通过率。表中的“证据索引”对应附录 C 的编号。

填写依据：[整体设计](agent-design.md)、[运行协议](agent-architecture-and-runtime.md)、[评测说明](agent-evaluation.md)和[测试集说明](../evals/standard-test-dataset.md)。本模板不改变这些文档规定的产品契约和评分口径，不预设任何验收结论。

## 4. 测试方法与通过标准

### 4.1 分层方法

| 测试层次 | 方法与可证明内容 | 结论边界 |
| --- | --- | --- |
| 离线工程测试 | 用离线单元、集成或模拟请求验证公共契约、阶段协议和异常行为 | 工程通过不证明真实模型的业务理解正确 |
| 标准资产基线 | 通过 preflight 与 baseline 核对资产合法性、标准模板和 expected 的一致性，区分默认与 full-scope | 不代表 Agent 自动生成正确率 |
| Schema-only | 调用 `propose_schema()`，复验提案并分别审阅业务合理性、规则遵循和一致性 | 不执行 TTP，不产生模板严格分数或可解析性结论 |
| TTP-only | 调用 `generate_from_schema()`，以固定标准 Schema 验证模板及 records | 不评价自动 Schema 推断质量 |
| End-to-end | 调用 `generate()`，独立验收后结合 Schema 和解析内容审阅计算联合通过 | 不使用人工字段布局的 records 全等评分或 TTP-only 叶子分数 |

### 4.2 统计约定

- 定义统计单位：数据集、输入、trial、模型调用、模板提交和提案 pair 分别计数。跨用例汇总注明宏平均或加权方式，不混用分母。
- Schema 合法性、业务可接受性、政策遵循及命名／层级一致性分开记录；相同错误不算业务正确。业务可接受比例以全部计划 trial 为分母。
- 两两契约比较仅使用同用例生成成功且复验通过的提案；有效提案不足两份时不可计算一致率。另列计划 pair、有效 pair、已审阅与可判断 pair 数，不将 pair 当作相互独立的重复运行。
- 固定 Schema 下的严格通过要求生成成功、独立验收通过、输入映射正确且 records 与 expected 深度全等。对象键顺序忽略；数组顺序、类型、缺失、空字符串和 `null` 严格区分。
- End-to-end 联合通过要求生成及独立验收成功，Schema 与解析内容审阅均可接受且证据齐全；未知、失败与缺失审阅保留在计划 trial 分母内。政策遵循另列，不擅自改写已有联合指标。
- 失败、未知、不适用、缺失审阅及遥测缺失分别记录；可能重叠的分类注明关系。不得删除失败 trial、补零或把脚本退出成功等同于业务通过。
- 不同模型、提示、预算、输入范围或审阅口径的结果分表展示。复跑单独登记原因、范围和批次，不覆盖原结果。

本报告采用的聚合与缺失处理说明：**【待填写：各表的统计单位、聚合方式、计划分母及异常处理依据】**。
