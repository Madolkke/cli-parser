# 模型输入拒绝排查

## 现象边界

上游返回 “Invalid prompt” 一类输入拒绝时，只能确认供应商在生成前拒绝了本次模型输入。错误文本通常不能指出具体片段，也不能证明仓库中的某个词单独触发了拒绝。

本项目有两条不同的模型请求链，排查时必须先区分：

1. Codex 等仓库协作 Agent 会把适用的 `AGENTS.md` 作为高优先级上下文。此时根说明过长或语义密集，可能影响请求分类。
2. 产品内 `TtpGenerator` 不读取 `AGENTS.md`。它只发送 `prompt.py` 中的阶段提示、阶段工具定义、采样输入，以及模板阶段的冻结 Schema 和受控工具结果。此时应检查阶段提示、输入样例、Schema、工具结果和兼容供应商行为。

## 本次发现

整理前的根 `AGENTS.md` 约 27.5 KiB，集中包含以下容易产生歧义的词群：

- 缩写 `TTP`。本项目指 Template Text Parser，但在其他语境中也常被解释为安全领域术语。
- 网络设备 CLI 与系统操作相关词同时出现，包括命令、执行工具、外部地址、动态扩展和网络查询等。
- 调试存储、API Key、凭据过滤、本地无认证界面及路径边界等运维说明集中出现。
- 大量“禁止、拒绝、绕过、终止”等强制措辞，与工具调用和解析器实现细节密集组合。

这些内容都是防护约束，没有不当目标；风险来自长上下文中的词义组合和缩写歧义。不能据此断言它们就是某次拒绝的唯一原因。输入样例自身、供应商额外规则、模型版本和兼容网关也可能参与判定。

## 已采取的整理

- 在根说明开头明确 `TTP = Template Text Parser`，并说明产品只解析已取得的文本。
- 将根说明缩短为稳定契约、确定性门禁和文档路由；详细运行时、评测、观测与界面规则继续由专题文档维护。
- 明确禁止把 `AGENTS.md` 拼入产品 Agent 的运行时模型上下文。
- 用能力边界描述替代长串敏感实现名，但不削弱代码中的白名单、隔离解析和最终验收。

## 建议排查顺序

1. 记录失败链路：`codex`、`schema` 或 `ttp`，以及 request ID、阶段、轮次、模型、base URL 主机名和 HTTP 状态；不要记录请求正文或 Key。
2. 判断失败发生在首次模型调用还是工具结果进入后的后续调用。首次失败优先检查 system/task/输入；后续失败优先检查新增的工具参数和工具结果。
3. 用同一模型和同一配置做有界二分：先只保留无真实输入的最小阶段提示，再逐项加入工具 Schema、单份脱敏输入、冻结 Schema 和工具结果。测试材料必须使用人工构造的非敏感文本。
4. 若只有特定真实样例失败，在本地检查其主题和异常字符串；不要把原始语料提交到额外的第三方服务做分类。
5. 若 OpenAI 官方端点与兼容端点结果不同，将问题归到供应商兼容层；保留响应 request ID，按供应商支持流程提交。
6. 若所有输入都在同一阶段稳定失败，优先缩短并去重 `prompt.py`，保留正向任务说明和必要边界，把可由确定性工具保证的细节从模型提示移回代码校验与 ToolResult。

## 实现改进建议

- 将供应商输入拒绝规范化为独立 issue code，例如 `model_input_rejected`，不要与超时、鉴权、限流或普通模型失败混在一起。
- 安全记录响应 request ID、HTTP 状态、阶段、轮次、尝试序号和供应商主机名；不保存异常正文，因为兼容供应商可能回显请求片段。
- 为两个阶段提供离线 prompt snapshot 测试，断言 `AGENTS.md`、本地配置、observer 事件和上一阶段消息不会进入请求。
- 增加人工构造的 prompt 组件二分脚本，只打印组件名称、字符数和结果类别，不打印正文。该脚本属于开发诊断入口，不进入产品 API。
- 不通过删除确定性安全校验解决输入拒绝。优先减少模型上下文中的重复说明，安全规则继续由 Schema 校验、模板白名单、隔离解析和 Agent 外终验执行。

## 参考

OpenAI 的 [Moderation 指南](https://developers.openai.com/api/docs/guides/moderation) 说明，安全相关的正常讨论也可能产生 flag，应结合类别与分数作为应用侧信号；工具参数和工具结果进入对话内容时也属于被检查的输入内容。该说明支持按组件定位，但不提供本错误的逐片段归因。
