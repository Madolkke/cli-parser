# Roadmap

## Huawei ONT：受控支持 TTP 动态路径合并

状态：规划中。当前不放开产品门禁，不升级依赖，不启用宏或解析后业务合并。

### 动机与当前处置

`huawei_smartax.display_ont_info_0` 的状态表、描述表和端口汇总属于同一批端口与 ONT。
旧资产只覆盖状态表，忽略描述及汇总，不能作为完整性评测基线。
该用例已从 `evals/datasets.toml` 移除，原四件套保留在
`evals/disabled_test_sets/huawei_smartax.display_ont_info_0/`，不参与标准评测；ID 15 保留供恢复使用。
旧 Schema、模板和 expected 仅供审计，恢复前必须依据输入重新核对。

原生 TTP 的无宏合成实验已证明，动态 group 路径与 `**` 可以将同一端口的描述和汇总
合并为字典；尚未完成 Huawei 四份输入的端到端完整合并验收。
当前项目拒绝动态 group 路径和 `**`，受限 Schema 也只支持固定字段的封闭对象。
因此不能仅增加一个 TTP 语法白名单条目就恢复该用例。

### 实施计划

1. **冻结结果与 Schema 设计。** 比较按端口/ONT 动态键组织的字典和现有语义数组。
   明确重复端口、相同 ONT ID、输入顺序及原始键值的处理。不通过宏、动态 Python、
   隐式后处理或丢弃业务字段绕开限制。动态键若成为正式结果，需设计受限映射 Schema，
   明确允许的关键字与映射值结构，不直接允许任意 `additionalProperties`、正则或无限层级。
2. **静态门禁最小扩展。** 为 group 路径定义独立语法，只允许受控静态段、合法捕获字段
   引用及明确位置的 `**`。检查字段引用、路径层数、长度和结果复杂度；宏、lookup 外部
   数据、动态求值、命令和网络访问继续禁止。解析仍在隔离 spawn worker 中完成。
3. **验证键与合并语义。** 检查端口值内空白、点、斜杠、星号、花括号及保留名称是否会
   改变路径解释；检查空键、重复键、跨端口 ONT 重号和冲突值。明确覆盖行为是否丢失
   原文事实；不得把“后值覆盖前值”默认为正确。不能忠实表达重复实体时不放开门禁。
4. **贯通产品契约。** 同步 Schema 提交/注入校验、records 回验、字段覆盖反馈、安全
   issue 路径、提示与文档。动态键可能包含业务数据，不得直接进入普通日志或公开诊断；
   反馈继续采用有界受控路径。公共结果若调整，须先明确兼容边界，再修改实现。
5. **离线证据与回归。** 合成测试覆盖乱序描述、缺描述、占位字符串、汇总缺字段、
   多端口同 ONT ID、单 ONT、重复与冲突键、恶意键、结果上限及多输入隔离。
   每组断言完整结构和值，而非只断言解析成功；已有合法模板与 Schema 回归必须通过。
6. **恢复完整 Huawei 资产。** 根据原始输入人工核对完整 Schema 和 expected，编写
   无宏共享模板。覆盖四份输入的状态、描述、各端口汇总；汇总原值不复算，
   `ONT_NO_DESCRIPTION`、`-` 等值忠实保留，缺失 offline 不补值。
   通过默认及 full-scope preflight/baseline 后移回 `evals/test_sets/`，恢复 ID 15，
   同步注册表、来源说明和计数。真实模型回归的范围、预算和采用门槛另行确定。

### 放开条件

- Schema、动态键路径与合并语义均有明确且受限的契约。
- 白名单、隔离 worker、Schema 回验、反馈投影和恶意输入测试通过。
- 完整离线 pytest、Ruff、格式检查以及默认/全量 preflight、baseline 通过。
- Huawei 四份输入完整字段和值通过独立标准答案校验；现有 Easy/Medium 保护范围另行回归。
- 原生语法可行与当前产品正式支持分别报告，不以合成实验成功替代恢复验收。
