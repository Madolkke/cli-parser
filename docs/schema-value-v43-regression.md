## 目标改善和扩大问题

Fortinet 四份提案均分别表达设备型号、固件版本、构建标识、日期和发布类别，并拆开
数据库版本与更新时间、不同模式的计数。Port-channel 四份均把逻辑接口与附加状态、
成员接口与附加状态分开。后者两份虽然拆分正确，根粒度仍错误；不能把这两个维度混算。

| 机制 | v40 受影响 trial | v43 受影响 trial |
| --- | --- | --- |
| Fortinet 应拆未拆 | 3/4 | 0/4 |
| Port-channel 应拆未拆 | 1/4 | 0/4 |
| HP 已有空槽被要求省略 | 1/4 | 2/4 |
| SD-WAN 业务限定错误 | 1/4 | 1/4 |
| SD-WAN 漏掉末列空槽 | 1/4 | 0/4 |
| SD-WAN 根误建成单条连接 | 0/4 | 1/4 |
| SD-WAN 将同一多行列标签拆成两列 | 0/4 | 1/4 |
| Port-channel 根误建成单组 | 0/4 | 2/4 |
| OSPF 拒绝后覆盖缩减 | 0/4 | 0/4 |

SD-WAN #2 的限定和过度拆分属于同一份提案上的关联问题，不相加为两份失败。
六份需修正提案的具体证据如下：

| 用例／trial | Trace | 受控结论与问题路径 |
| --- | --- | --- |
| HP #1 | `b64867e2-a9aa-7020-7ed1-5619ca4ec0f1` | 明确要求空表格槽省略；`/ports/*/name`、`/ports/*/config_mode`、`/ports/*/speed`、`/ports/*/media_type` |

空槽问题的依据是明确捕获说明，不是字段为 optional 就判错。SD-WAN #2 第一份因
required 放入 properties 而拒绝，修订只修正结构合法性，错误的列理解随即冻结。
这些结果支持“合法后立即冻结缺少语义纠正环节”的局限，不证明增加确认必然改善。

没有把合理表达差异判为错误：图例是否建模、固定时间章节用 object 或数组、标识符
用 string 或 integer、显式单位的数字或带单位字符串、整型号是否含厂商前缀等，
均依据当前可见输入审阅。MikroTik 发布通道单列或保留整体、VPN 格式不统一的算法
说明保留整体，未作为新的业务错误。未发现机械拆开版本点号、时间戳或完整时长的问题。

## 契约漂移与说明语义

自动比较观察到路径差异 74/81 对、容器类型差异 3/81、同路径标量类型差异 4/81、
required 差异 7/81、约束差异 6/81、同路径说明文字差异 79/81。
宏平均契约一致率 3.57%，按有效 pair 加权为 3.70%；路径重合度分别为 57.51%、59.64%。
MOS 只有三对，所以这两类平均不再相同。

人工关联已能确认的对应字段后，观察同义命名 67 对、类型选择 19 对、结构归属 17 对、
覆盖 14 对、拆分／合并 12 对、required 7 对、约束 6 对。类别可重叠，不能求和为失败数，
也不能把上层容器改名后的全部下游路径计成多项独立根因。

81 对中 66 对都是合理提案，15 对至少一份有明确问题。说明语义等价 43 对、不同 38 对；
“不同”也包括合理的数值表示、业务值边界和拆分选择，不等同于错误。
三对合同完全一致且说明语义等价，分别来自 S300、TACACS 和 VPN，各一对。

最直接的限制仍是：本轮只收紧值拆分，其他命名、容器、数字、required 和约束选择
继续开放。局部建模改善没有使同一输入稳定落入一个契约。也不能将其全部归因于 MOS：
除去该用例，v43 仍为 3/78 契约一致，历史 v40 为 8/78。

## 验收与决定

实现时离线 pytest 1137 passed、3 live skipped；JavaScript 31 项，Ruff、格式和 diff
检查通过。默认及 full-scope preflight 无失败，baseline 均 16/16，full Huawei smoke 1/1。
本次受限审阅通过标准 `schema-review` 引用、分类及数量校验；这验证文件协议，
不是独立证明审阅判断正确。

v43 的合成示例和目标拆分方向成立，真实模型在两个目标用例也遵循了指导；但生成
55/56、可接受 49/56、合理一致 3/84，均未达原门槛。HP 空槽扩大和新根粒度错误也
单独构成失败条件。恢复 v40 是执行原采用规则，不否认已观察的局部拆分收益。

后续首先修复工具参数反馈与无进展循环，并把允许 Schema 能力与实际门禁统一；
建模优化则需同时减少合法决策空间，分开验证同一计划编译的确定性和不同生成的
建模一致性。解析效果必须通过端到端运行单独证明，不能从本批 Schema-only 推断。
