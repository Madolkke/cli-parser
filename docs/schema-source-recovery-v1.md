## 行为与边界

保留v48系统提示、提交工具、模型参数、采样、预算与协议。在Schema首次完整回复为
含推理、无正文的length时，若既有无工具修复、轮数及deadline仍允许，向下一轮原提醒
附加一次原文定位辅助。原始任务保持不变；不读取Trace或标准答案，不恢复被拒绝草稿。
正常首轮和TTP请求不变，不增加模型调用、不改推理强度或输出预算。

辅助来自该请求实际已发送的采样对象：输入序号、行序号、Unicode字符[start,end)、
逐字最大非空白词项和原行长度。不是列解析、Schema编译或业务字段计划；token不等于
字段，字符位置不等于终端显示列。程序不选择表头、不分配上层限定、不生成名字。

每份完整输入只考虑前12行，全局256词项，含说明与JSON的整条辅助消息至多16KiB。
超限整行省略，词项不截断；所有省略显式计数。被采样截断的输入整份跳过，避免将
采样标记或半行当原文。完整原输入自带的标记则作为普通数据，不用字符串猜来源。

辅助说明要求核对原始独立列与空槽；证据无法确定的上层限定不写成已证实业务含义，
仍保留明确底层标签与独立字段，并按原规则处理冲突。此规则是通用恢复指导，不含
SD-WAN标签、参考Schema或具体字段答案；只加在本次触发的恢复消息中。

附加前用实际Agent上下文、工具与候选消息计数；必须低于原初始上下文比例、原生压缩
阈值及上下文减输出预留的最小值。存在摘要、原始输入消息已不在上下文、计数失败或
不够容量时跳过，不触发压缩来容纳辅助。估算仍是现有近似计数，不宣称精确token保证。
deadline包围本地准备和计数。来源限定于当前Schema模型实例，TTP不会继承该数据。

保留独立length工具拦截，截断参数不能经修复误冻结。辅助只出现一次，后续按原协议
处理；它不能保证列归属正确，也不能让两份错误Schema因一致而通过业务验收。
运行时单独标记`schema-source-recovery-v1`，提示版本仍v48，报告明确额外恢复指导。
