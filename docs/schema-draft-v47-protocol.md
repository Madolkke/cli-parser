# v47 轻量 Schema 草稿实验

本实验比较 v44 直接生成（A/direct）与 v47 轻量草稿编译（B/draft）。默认产品仍是
`ttp-generator-v44-schema-runtime-contract-zh-cn`；候选版本为
`ttp-generator-v47-lightweight-label-and-root-structure-zh-cn`。实验实现固定于 f7b9a16。24 次预试未达到门槛，候选运行接线已撤下；以下保留原方案与采用规则，实际结果见 [预试报告](schema-draft-v47-pretrial-regression.md)。

## 产品与实验边界

三个公共生成 API、公共请求和结果、外部 Schema 注入、TTP 提示及解析、默认预算、依赖
和标准四件套不变。B 只替换 Schema 阶段的内部工具及来源展示。类型、required、说明、
约束和拆分判断继续由模型按 v44 政策决定；不引入实例枚举、字符坐标、业务角色、
捕获计划或确认轮次。

程序保证合法引用、确定性名称规范化和结构组装，不能证明标签完整、限定归属正确或
重复实体全部被识别。即使根固定为 object，模型仍可能错误地把一个实体平铺到根。
同一草稿编译一致、同一输入建模一致和最终业务正确必须分别报告。

## 私有草稿 v1

Schema 阶段只注册 `submit_schema_draft(draft)`。工具顶层只接受一个对象 `draft`。
内部对象拒绝未知键和隐式类型转换：

- 草稿：整数 `version=1`、`fields`，以及可选 `attributes`，根隐式为单次完整输出。
- 属性：互斥名称表达 `name`、明确布尔 `required`、`node`。
- 节点：`type` 是当前六种 Schema 类型之一；object 使用 `fields`，array 使用匿名
  `items`；标量无子节点。可选 `attributes` 只含校验器同声明源支持的注释及类型约束。
- 来源名称：`{"source":[{"line_id":"i0f0l1","quote":"Asset Ref"}]}`。
- 语义兜底：`{"fallback":"asset_ref","reason":"unlabeled"}`，必要时带 `source`。
  原因限定为 `unlabeled`、`ambiguous_source`、`invalid_name`、`conflict`、
  `split_component`。程序能验证的非法名称及冲突原因必须成立；其他必要性由审阅判断。

上限为 64 KiB、256 个属性、编译后 16 层、1024 条标签引用。超过上限拒绝，不能删字段、
截断值或静默选择部分草稿。数组 items 没有名称及 required，可为标量、object 或 array。
编译生成 Draft 声明、properties、required、items 及封闭对象，保留模型的类型、注释
和合法约束；编译结果经原校验器复验后深拷贝冻结。无确认工具。

来源行只从实际发送的采样片段生成；行号与原文数据分离。完整行才可作为命名来源，
截断行仍可用于模型理解但不能提供标签引用。引用须是该行唯一的连续原文子串，不可
截断英文/数字词项，多片段不能跨输入或采样缺口拼造标签，多行表头保持原顺序。
不能机械把邻列、整表标题或父容器前缀加入名称。原文本身形似行号或省略标记仍是数据。

ASCII 标签转小写，词项分隔标点及空白转单下划线，去两端布局符号；词序、缩写和选中
限定保留，不改单复数。非法名称使用有理由的合法语义名称；同父冲突在构造 properties
前拒绝，不覆盖、编号、截断或移动字段。遗漏整个限定词可能仍合法，这是语义审阅项。

来源展示纳入上下文拟合；只有最后一次实际发出的来源映射能用于编译。TTP 阶段继续
独立采样原始输入，不接收行号、草稿或 Schema 历史。外部注入不经过草稿，也不改名。
协议失败止损和工具边界分类沿用 v44，草稿内容拒绝属于合法入参后的业务校验拒绝。

## 验证、隐私与观测

离线使用独立合成输入；实际提示示例直接提取测试。覆盖所有允许节点和约束、required
归属、名称规范化及兜底、采样边界、冲突、修正冻结、取消、预算、API 与阶段隔离。
明确保留两个反例：引用完整词但丢失限定仍可能通过；单实体错误平铺根仍可能通过。
真实模型请求不接收评测答案、事实清单或审阅结论。

安全产物只保存计数、比例、固定分类、受控问题路径及 Trace/span 标识。来源正文、
quote、草稿、Schema、说明、模板、records、签名或内容哈希不导出。正文只在授权的
Laminar 只读通道内存审阅。完整编译 Schema 仅进入明确的敏感观察通道与后续产品阶段。

沿用 runner v5、metrics v2、七维 Schema 审阅、逐对说明语义审阅及独立解析审阅。
补充标签命名数、兜底及原因、来源/冲突拒绝、草稿字节数、来源展示开销、采样量、
协议失败与输出截断。不存在观测时记未知；不能从框架完成状态猜供应商 finish_reason。

完整 pytest、JavaScript、Ruff、格式、diff 检查及默认/full-scope preflight/baseline
通过后提交。AST 比较 TTP 提示与任务构造不变，核对标准资产未发生本轮修改。

## 固定真实运行

唯一入口为 `scripts/run_test_sets.py`；私有 A/B 工厂请求局部隔离，无长期产品开关。
同一资产快照，内存比较原始输入，按用例 AB/BA 轮换入队，全局并发 4。
来源展示开销和由此引起的采样差别独立报告，不能误报为原始输入不同。

两组均为 deepseek-v4-flash、temperature 0、非流式、8192 输出预算、128000 context、
HTTP I/O timeout 120 秒、模型重试 2；每请求 1800 秒、26 轮、18 次 TTP 提交、3 次
独立测试。Thinking 计数及 DeepSeek 参数映射沿用 v44；8192 包含推理输出。

先确认 Docker、Laminar 写入、flush、回读和正文访问，记录 revision、dirty 状态与
所选输入。保留无关脏文件。运行期间不调整行为；出现实现缺陷则停止该批并报告实际
消耗，不修好后拼接、补跑或追加请求。

### 24 次预试

Schema-only，A/B 各 ID `3,7,9,11,17,18`、默认 `001.txt`、每例两次。
B 进入正式阶段需全部满足：

- 生成及复验 12/12，全部 trial 与有效 pair 审阅完整。
- 可接受数不低于同期 A；六对计划比较中合理且契约、说明语义一致至少一对且不低于 A。
- 无新增明确“用例＋错误机制”，原机制受影响 trial 数不扩大，包括根粒度。
- 无需改变实现或提示才能继续实验。

不达标结束，保留 v44。Schema-only 可解析性为未测。

### 条件执行 112 次正式对照

end-to-end，A/B 各 ID `1,3,5,6,7,9,10,11,13,14,16,17,18,19`、默认 `001.txt`、
每例四次；从预试到正式不能按用例调提示。使用现有独立业务事实清单，只据原文核对
其适用性，不按新候选修改评分事实。

U 为合理 Schema 数、J 为合理且契约与说明语义一致 pair 数、K 为四次均合理一致用例数、
E 为 Schema 可接受且完整生成/终验/解析内容审阅均通过的 trial 数。采用需全部满足：

| 指标 | 条件 |
| --- | --- |
| 工程与证据 | 离线通过，全部审阅完整，分歧已解决 |
| Schema 可靠性 | B 冻结提案及复验 56/56 |
| 合理性 | U_B >= U_A |
| 联合一致性 | J_B >= J_A + 6；合理提案中一致率不低于 A |
| 用例一致性 | K_B >= K_A |
| 命名漂移 | 同义命名差异有效 pair 率低于 A，分母与数量单列 |
| 解析保护 | E_B >= E_A；A 中 4/4 用例在 B 中保持 4/4 |
| 错误保护 | 无新增明确机制，既有机制影响 trial 数不扩大 |

缺少有效比较或证据不能视为通过。初审隐藏组标签，但产物形态可能提示来源，不声称
完全盲法。全部失败、新错误及采用边界项由独立审阅者复核。合理表达差异不自动判错；
同样错误的两份 Schema 不能进入 J。

## 交付与采用

上限 136 次公共生成请求，不补跑；底层模型调用及重试另计。分实现、预试结果及必要
回退、条件正式结果与采用三阶段提交。采用后只留 B 默认路径，移除实验选择；未采用
保留 A 及可靠性修复，撤下 B 接线，保留独立诊断与脱敏报告，并复验工程检查。

最终分别回答提交可靠性、标签命名与兜底漂移、根粒度、业务合理性及解析效果。
允许一致性改善且合理性和解析不下降的局部收益，但不能称为解析已改善。
这些门槛用于工程采用，不是统计显著性结论，不自动开始下一轮优化。
