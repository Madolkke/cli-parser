# v48 SD-WAN 输出预算恢复实验

本轮只将显式 Schema-only 运行配置的 `max_tokens` 从 8192 提高到 16384，验证
SD-WAN 是否能在推理耗尽前完成提案，同时保护三个已完全稳定的用例。产品继续使用
`ttp-generator-v48-schema-naming-and-structure-policy-zh-cn`，产品默认预算保持 8192。
不修改提示、公共 API、协议、推理强度、重试、超时、采样、依赖或标准测试资产。

## 执行与门槛

唯一执行入口为 `scripts/run_test_sets.py run --mode schema-only`，调用公共
`propose_schema()`。本轮最多 16 次公共生成请求，不补跑、不搜索其他预算。

1. ID 11 SD-WAN 默认 `001.txt`，重复 4 次、全局并发 4；全部完成后审阅。
2. 仅当 4/4 生成、复验、业务合理及适用命名/结构政策通过，且证据完整时，运行
   ID 10 NXOS interface、ID 13 MikroTik、ID 14 Arista，各默认 `001.txt`、重复 4 次，
   全局并发 4，共 12 次保护回归。
3. 保护用例分别要求 4/4 生成、复验、业务合理及政策通过，各 6/6 pair 合理、完整契约
   和说明语义一致。不要求与历史 Schema 逐字相同。

SD-WAN 的一致性照常报告，不增加六对完全一致的门槛。任一阶段不达标即结束，保留完整
结果，不推广配置、不调整后继续拼接实验。证据不足不算通过。

两阶段均使用 deepseek-v4-flash、temperature 0、非流式、context 128000、HTTP timeout
120 秒、模型重试 2、每请求 1800 秒及 26 轮；TTP 提交 18、独立测试 3 在本模式不使用。
Thinking 配置保持未显式设置；除 max_tokens 外逐项匹配 v48 已记录 model/policy。
输出上限包括推理 Token，不是可见 Schema 的独立额度。每次独立生成器，同批重复使用
标准 runner 固定的内存输入快照，不传入人工答案或其他 trial 结果。

## 运行前与审阅

实际 SDK MockTransport 对比 8192/16384，仅输出预算不同，官方 DeepSeek 端点正确发送
`max_tokens`。离线核对四例采样、上下文拟合与截断事实；运行相关配置、预算及 Schema-only
测试，默认/full-scope preflight 和 baseline，以及 Ruff、格式和 diff 检查。
核对产品目录及标准四件套没有本轮修改。

真实运行前完成 Docker、Laminar 探针写入、flush、API 回读和正文访问检查，记录 revision、
dirty 状态、输入路径及有效配置。服务异常时先恢复，不启动模型。

使用 runner v5、metrics v2 和 schema-review v2，逐条审阅全部已运行 trial 及有效 pair。
完整执行最多 16 条 trial、24 对 pair。SD-WAN 重点核对多行表头限定、相邻列归属、空槽、
占位字符串及业务覆盖；工具提交成功不等于业务正确。失败 trial 的业务及政策证据不足
保留为未知。记录提交/拒绝、length、无工具回复、轮次、首次冻结、Token、耗时及采样事实。

正文仅通过已授权 Laminar 只读通道在分析内存处理，不落盘、不保存内容哈希、不回灌模型。
本地仅保存受控分类、数值、有界路径及 Trace/span 标识。观测缺失不补零、不补跑。

## 交付与解释边界

先提交协议及相关离线验证，再提交真实结果和受限审阅。保留已有无关工作区修改。
全部通过时仅保留 16384 作为显式 Schema-only 配置；该参数由 Schema/TTP 共用，不能
以本轮结果提高整个产品默认值。未通过或证据不足时保留当前默认配置，本轮结束。

这是与已有 v48 的历史比较，没有同期 8192 对照；历史未保存内容指纹，不宣称输入正文
逐字一致已经证明。供应商文档说明旧模型名称存在别名路由，名称相同不证明后台版本固定。
不把差异全部归因于预算，不作统计显著性结论。未运行 TTP，**可解析性未测**。
