## 实现和离线验证

实现提交为 `18523e633c5b35e59420fd751d397e8381b7af77`，被测提示为 `ttp-generator-v41-schema-record-scope-and-string-fidelity-zh-cn`。只改 Schema 系统提示与提交工具说明，明确整份输出的根、重复实体、所属子项，以及 description 的字符串保真；增加一份独立合成正例。公共 API、校验器、冻结协议和资产未改。

提示中的完整 Schema 直接提取后通过共用校验，独立预期覆盖多个实体、可选子项、空槽、缺键及不同实体数量。失败对照证明：单实体根可通过 Schema 门禁却不能表达整份预期 record；省略、清空或清洗占位字符串都可能通过同一 Schema。这证明确定性校验存在这些语义边界，不证明模型必然遵循提示。

模拟 OpenAI transport 验证新系统提示与工具说明到达 Schema 请求，只有冻结结果交接到 TTP 阶段。AST 比较确认 TTP 系统提示、两阶段重试提示和全部任务构造未变。实现前验收：pytest **1087 passed / 3 live skipped**，JavaScript **31/31**，Ruff、格式、diff 检查通过；默认和 full-scope preflight 无失败，baseline 均 **16/16**，full Huawei smoke **1/1**。

## 语义证据与边界

| 机制 | 受影响 trial | 路径 | Trace ID |
| --- | --- | --- | --- |
| 根对象仍描述单会话 | VPN #3 | `/` | `f1ace0ad-0f90-0497-48c2-078c478ed677` |
| 独立版本／日期／模式计数保留为复合字段 | Fortinet #1 | `/version`、`/virus_db`、`/virtual_domains_status` | `097ca561-b42e-7c75-fa3f-47142f2de6df` |
| 同上 | Fortinet #2 | 同上 | `144211f7-ba0f-0d15-69e6-761d13f5089a` |
| 同上 | Fortinet #3 | 同上 | `4c656d24-373a-5b45-2813-c3f1125c7458` |
| 同上 | Fortinet #4 | 同上 | `7cb07a22-8be0-83b3-2a5b-37a51664a1db` |
| description 明确要求省略已存在的空槽 | HP #2 | `/ports/*/name`、`/ports/*/config_mode`、`/ports/*/speed`、`/ports/*/port_type` | `98b85e1b-f3b7-ad73-52f9-286cd5fea981` |

Port-channel 四次都把通道及其成员放入所属数组，VPN 三次如此、一次仍把单会话属性放在根层。后者连共享标题也按实体可选字段处理，证据支持根粒度错误；不能把它归因于压缩，当前没有相应压缩观测。

NXOS interface 四次都明确保留占位字符串；Palo Alto 同样保留值内符号。HP #2 的问题与“字段可选”不同：说明明确要求空列省略，改变了已展示空槽的表达；HP #3 只是较宽松的可选性且说明允许空值，沿用 v40 口径判为可接受。

Fortinet 四次均倾向于按标签整值保留，复合字段未拆开。该行为与保真措辞可能存在张力，但本轮合并修改、没有消融，不能断言由某一句提示导致。后续如重新实施，应把“先识别独立逻辑值，再保留每个值”与“整条属性行原样保留”明确区分，先设计合成对照；本轮不自动实施。

SD-WAN #4 使用 `/control_connections/*/group_id`，虽未在字段名加入全部上层表头词，但说明定位 GROUP ID 列，且明确空槽保留；区别于 v40 无说明的泛化 id，本轮无足够证据判为明确业务错误。没有把缺少某个词机械当成命名错误。

共享标题是否单独建模、固定时段选择数组、标识符 string/integer、设备型号保留厂商前缀等差异，只要能表达当前输入且无明确业务矛盾，均不判错。OSPF 的标签说明存在个别措辞不精确，但附带的具体标签边界足以识别字段；MOS 数字精度说明未要求舍入或改值，不据此判为已发生内容错误。

56 份七维审阅、计数、冻结时延、结构描述统计和 span 标识见 [脱敏结果](schema-only-v41-results.json)。Trace 正文仅在 Laminar UI 阅读，本地不保存原文、提案、description、结构签名或内容哈希，也不向产品模型回灌 Trace。

## 后续建议

优先分离验证根粒度指导与字符串保真指导的影响，并对“逻辑值拆分”与“值内符号保留”建立清楚边界，再考虑新版本。当前默认保持 v40。本轮只证明合成示例成立、若干模型行为有变化；小样本语义可接受数从 49 增至 50，仍未满足采用规则，不能宣称稳定改善。
