本轮只扩展评测，产品保持 v40。完成 14 个用例各 4 次、全局并发 4 的 56 次
Schema-only 运行，全部最终提案与 84 对有效比较均在 Laminar UI 只读审阅。
没有补跑，没有运行 TTP。**可解析性未测**。

## 明确问题与合理差异

七份明确问题影响四个用例：

- Fortinet #2、#3、#4：版本复合值未拆分；#2 还合并数据库版本与时间，#2/#3
  合并不同模式计数。对应 decomposition，不按缺失子路径数量重复算根因。
- HP #1：已存在的空白列槽被说明要求省略，影响 `/ports/*/config_mode`、
  `/ports/*/speed`、`/ports/*/type`。Schema 可选本身不是错误，明确省略要求才是证据。
- SD-WAN #1：`/control_connections/*/controller_id` 未保留多行表头的组级限定，
  说明也只解释为控制器 ID；#3 完全缺少该列的空槽表达。分别记字段含义和覆盖问题。
- Port-channel #4：逻辑接口及状态、成员接口及状态未分别建模，见
  `/port_channels/*/port_channel` 与 `/port_channels/*/member_ports/*`。

本批没有观察到根对象直接代替重复实体、或将非空占位字符串改为空值的最终提案。
这不是产品修复证明：本轮产品并未改变，也不能从四次样本推断这些机制已消失。

合理差异包括：Broadcom 的 `/switch_id` 与 `/switch`；TACACS 根数组的不同命名；
标识符选择字符串或整数；固定时间章节选择 object 或带 period 的 array；OSPF 单个
可见 area 放根字段或放 areas 数组；Arista 内存保留带单位字符串或明确单位的整数，
uptime 保留整值或拆成时间组成量。这些都能表达当前展示输入，不因与人工 Schema 不同扣分。
图例是否建模属于非主要业务覆盖选择。业务复合值拆分与一项逻辑值的多个格式组成部分
不是同一规则：计数/版本/时间各自可独立消费，而完整时间字符串或算法说明可作为一个值。

约束审阅只基于本次可见输入和基本业务类型语义。非负计数、非空实体标识没有当前
可见冲突；数组 minItems=1 未据隐藏输入判错，其跨空输出适用性未验证。
“可接受”表示未发现当前可见业务错误，不证明契约能覆盖未见输出。

## 漂移来源

自动统计不匹配同义字段，只比较相同路径，因此类型差异较少不等于类型选择稳定。
上层命名或移动导致整棵子树路径不同，也不能解释为多项独立错误。

| 自动差异 | 受影响 pair / 84 | 差异节点 / 可比较节点 |
| --- | --- | --- |
| 路径集合 | 71 | 1125 / 1914 |
| 容器类型 | 7 | 23 / 873 |
| 标量类型 | 6 | 6 / 873 |
| required | 4 | 8 / 742 |
| 校验约束 | 16 | 29 / 844 |
| title/description 文字 | 79 | 686 / 873 |

平均路径重合度 53.1%。每例均有六对，故宏平均与 pair 加权平均相同。
人工比较进一步识别同义命名 60 对、类型选择 32 对、约束选择 32 对、拆分/合并 18 对、
结构归属 14 对、覆盖 10 对、required 4 对；类别可重叠，不能求和为错误总数。
人工可以关联改名后的对应字段，故数量与自动同路径差异不同。

84 对中 67 对是两种合理表达，17 对至少一份有明确问题。说明语义等价 58 对、
不同 26 对、未知 0 对。“不同”也包括合理的单位/格式/拆分捕获方案，不等同于错误。
实际相同路径的说明文字未变化时，人工仍可在已确认对应的不同路径上观察措辞或含义差异；
因此人工 annotation_wording 与自动文字变化计数不是同一个指标。

## 验收与后续优先级

运行前完整离线 pytest 1131 passed、3 live skipped；追加汇总权重断言后，最终完整复验
1132 passed、3 live skipped。相关模块 45 项、Schema 相关入口 60 项通过。
JavaScript 31/31、Ruff、格式、diff 检查通过。
默认及 full-scope preflight 无失败，baseline 均 16/16，full Huawei smoke 1/1。
产品目录没有本轮改动。运行前恢复 Docker，确认探针写入、flush、SQL 回读及 UI 正文显示。

建议下一轮优先固定**字段命名与业务限定的取法**：合理提案之间同义命名最普遍，
同时能处理多行表头丢失业务限定的问题。先定义标签到字段名的稳定映射原则、父级
限定的保留边界和缩写政策，用新基线的联合指标验收，避免只是换一批同义词。

其次固定复合字段的拆分粒度（本批两例四份明确问题），再统一类型/单位和约束的
保守选择。空槽说明应作为持续合理性门禁，不能为提高一致率接受同样错误的描述。
解析闭环需另立评分方案；本轮没有可解析性数据。

旧 v40 共同指标为 56/56 合法、49/56 可接受、16/84 结构一致；本轮分别为
56/56、49/56、12/84。新增契约及联合指标仅以本轮作为首基线，不从旧数值产物补算。
相同可接受总数掩盖了问题分布变化；本轮不自动修改提示，也不据小样本宣称稳定退化。

完整安全数值见 [结果](schema-consistency-v40-results.json)，56 条七维审阅及 84 对结论见
