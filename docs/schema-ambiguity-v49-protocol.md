# v49 SD-WAN 歧义判断与提交收敛实验

以 v48 为基线，提示版本为 `ttp-generator-v49-schema-ambiguity-and-submission-zh-cn`。
仅改变 Schema 系统提示及提交工具描述，不保留失败草稿、不增加中间工具或模型调用。
公共 API、校验器、冻结、类型与 required 基本政策、TTP、采样和恢复协议保持不变。

## 指导与审阅口径

先按底层表头、数据排列和分隔确定独立列，保留明确空槽；再组合有可靠对齐、范围或
输入内重复证据的限定。位置与语义冲突时只用输入证据复核一次，不能机械挂到最近列，
或反复凭设备记忆、隐藏答案及评分偏好猜测。仍不明时采用底层标签或必要语义名称，
不丢列、不合并值、不虚构结构或限定。已完成选择无新矛盾不反复推翻。
description 只表达有证据的捕获边界。提交工具顶层只能有 result_schema；根 required
与 properties 同层且都在 result_schema 内。

SD-WAN 末列允许有证据的保守名称，例如 id，不强制猜出 controller_group_id。
错误限定接到组织字段、漏列、丢弃空槽或清洗占位值仍为问题。保守命名可以业务合理但
多次不一致，两者分别统计。该口径改变不用于重新判定历史结果或宣称模型准确率提升。

## 离线验收

实际提示示例使用独立合成材料，覆盖明确限定、错位歧义、同名底层标签、末列空槽、
缺行及符号值。提取工具参数 JSON，经入参和共用 Schema 校验及独立 records 检验。
反例验证工具顶层 required 拒绝，以及合法 Schema 仍可能有错误限定或清洗值。
MockTransport 验证实际请求指导、原名冻结及 TTP 隔离，原协议失败停止与恢复测试保留。

完整离线 pytest、JavaScript、Ruff、格式、diff 检查，以及默认/full preflight、baseline
全部通过后提交实现。AST 核对 TTP、任务构造和重试提示未变，标准四件套不修改。
已有脏文件只暂存本轮补丁，不夹带原有改动。

## 固定真实实验

唯一入口 scripts/run_test_sets.py run --mode schema-only，独立 propose_schema 请求，
默认 001.txt，每例四次，全局并发四，同批固定内存输入。最多 16 次，不补跑、不追加候选。

1. ID11 SD-WAN 四次全部完成并审阅；必须 4/4 生成复验、业务合理、适用政策通过，证据完整。
2. 仅首阶段通过后，运行 ID10 NXOS interface、ID13 MikroTik、ID14 Arista，各四次。
   每例须 4/4 通过，且各 6/6 pair 合理、完整契约与说明语义一致。

SD-WAN 一致性照常报告，不要求六对全等。配置恢复 8192 输出预算，deepseek-v4-flash、
temperature 0、非流式、context128000、HTTP120秒、模型重试2、每请求1800秒/26轮；
TTP 提交18和测试3在本模式不使用。除提示版本外 model/policy 逐项匹配 v48 的8192记录。
启动前验证 Laminar 写入、flush、回读和授权只读正文访问，记录 Git revision、dirty、
输入选择及采样。模型别名不能证明后台版本固定；没有同期对照。

使用 metrics v2/review v2 审阅全部实际 trial 和有效 pair，统计业务与政策、命名与层级、
完整契约、length、无工具、工具入参错误、用量、耗时及首次冻结。证据不足记未知。
Trace 正文只在授权只读通道的分析内存处理，不导出、不保存内容哈希、不回灌产品模型。
本地仅保存受控分类、计数、有界路径和标识。可解析性未测。
